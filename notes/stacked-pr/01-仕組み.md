# Stacked PR の仕組み

## 何のための機能か

画面・API・モデルの変更を 1 本の PR に入れると、差分が大きくてレビューが重い。
層ごとに PR を分けたいが、上の層は下の層に頼っているので、別々には出しにくい。
Stacked PR は、層ごとに分けた PR を「スタック」としてつなぎ、GitHub に管理させる機能。

## 積み方

```
main ← PR1（一番下） ← PR2 ← PR3（一番上）
```

- 一番下の PR の宛先は main（`--base` で develop などに変えられる）
- それより上の PR の宛先は、ひとつ下の PR のブランチ
- 各 PR の差分には、その層で足した分だけが出る

## GitHub が引き受けてくれること

- 下の層をマージすると、上の層の宛先が自動で付け替わり、rebase も GitHub 側で行われる
- 一番上の PR をマージすると、スタック全体が一度に入る
- PR の上部に段の番号、マージボックスに全段の一覧（スタックマップ）が出る
