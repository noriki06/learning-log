## 今日学んだこと

**制約をどこに書くかは、その値が「何を表しているか」で決まる。型が同じだからと同じ制約を貼らない。**

リマインドの送信時刻に「10〜19時に制限」と書いたとき、同じ日時型の `SurveyEvent.openAt` にも書くべきか迷った。
でも openAt は「回答を受け付け始める時刻」で、9/1 の決定は「案内を**送る**時刻」についてのもの。見積書でも「回答期間」と「送信時刻」は別項目として並んでいた。
openAt に書いてしまうと「回答は 0 時から受けるが、案内は 10 時に送る」という運用ができなくなる——それは誰も決めていない。
制約の置き場所を探すときは、型ではなく「その値が業務で何を意味するか」から辿る。

## つまずき

- **手元の設計資料が古くて「決まっていない」と誤認した。** engage-docs をローカルで検索して送信時刻の制約が見つからず、「記録が無い」と結論しかけた。実は手元が origin より 58 コミット遅れていた。`git fetch` して `git show origin/main:<path>` で最新版を読んだら、9/1 の議事録に「営業時間帯（10時〜19時）に制限」とあった → **調べる前に fetch。「無い」と言う前に、手元が最新かを疑う。**
- **ファイル地図（Artifact）が開けなかった。** コードの全文を HTML に埋め込んだところ、Svelte ファイルの `</script>` が HTML のスクリプトを途中で終わらせていた。さらに修正の途中で Python の `re.sub` が置換文字列の `\n` を改行として解釈してデータを壊し、その残骸が消しきれず居残った。3 段重なっていて、「直した」と言われた版も壊れていた → **公開後に実際に開いて確かめる。** 最終的に、最小限の DOM の代役を Node 上に作って全ファイル分の描画を走らせてから公開する手順にした。
- **「触ったファイル」の絞り込みで 2 件しか出なかった。** データは 18 件あったが、フォルダが閉じたままだと中のファイルが表示されない作りだった → 絞り込み中は該当ファイルの親フォルダを自動でひらくようにした。「見えない」と「無い」は違う。
