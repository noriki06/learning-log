DB について
- 場所は「ポート＋DB名」で決まり、守っているのは人間の運用だけ。だから雛形と同じ 13306/app を指していると混ざる。ポートと DB 名を両方変えて、間違った接続が必ず失敗するようにした
- flyway は「適用済みファイルを書き換えない」が絶対のルール。訂正は消しゴムでなく新しい行を足す（帳簿と同じ）
- ローカルのデータはコンテナと運命を共にする。構造は SQL が持つので、消えても migrateAll で戻る

4点セットについて
- モデル → SlickTable → リポジトリ → DI の依存は一方向。だから作る順番もこの通り
- ズレの発見しやすさが層で違う——コンパイラが捕まえるもの、起動時に分かるもの、実際にデータを通すまで分からないもの
- だから制約は破って確かめる。「二重参加できない」を実際に試して拒否されることを見た

作業の進め方
- Scala のエラーは連鎖する。3つ出ても原因は1文字だった。まず一番上を見る
- git は add → commit → push の順。順番が飛ぶと空振りする
- 1コミット＝1修正。メッセージが「〜と〜をした」になったら分けるサイン
